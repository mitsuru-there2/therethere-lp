# EmDash 公開前ToDo

今回は実装・ローカル検証まで。本番へのデプロイ、管理者登録、`therethere.studio` の切替は別途行う。

## 実装済みの構成

| 用途 | パス・設定 |
| --- | --- |
| 管理画面 | `/_emdash/admin`（サイト直下） |
| 全記事一覧 | `/blog` |
| AIアプリ診療所の記事一覧 | `/app-clinic/blog` |
| 共通の記事本文 | `/blog/{slug}` |
| 記事コレクション | `posts` |
| 診療所の抽出条件 | taxonomy `tag` の slug が `app-clinic`。表示名は「AIアプリ診療所」 |
| 公開条件 | `published` の記事のみ。公開日時の降順、1ページ12件 |
| データ保存 | Cloudflare D1 の `DB`、画像等は R2 の `MEDIA` |
| 予約公開 | Worker の scheduled handler と毎分の Cron を設定済み |

記事本文は共通URLに集約する。診療所の記事も `/blog` に掲載し、`app-clinic` タグが付いた記事だけを `/app-clinic/blog` にも表示する。言語切替は設けない。

## 1 公開用リソースの準備

- [ ] 現行 Worker `therethere-studio` の設定・バインディングと、戻せるデプロイのバージョンを記録する。
- [ ] 本番 D1 `therethere-studio-cms` を作成し、`wrangler.jsonc` の `DB` に `database_id` を設定する。既存DBを利用する場合は内容を確認してから接続する。
- [ ] 本番 R2 `therethere-studio-media` を作成し、`MEDIA` から利用できることを確認する。
- [ ] `npm ci`、`npm run types`、`npm run check`、`npm test`、`npm run build` を実行する。
- [ ] ビルドで生成される Worker 設定の `DB`・`MEDIA`・`SESSION`・`IMAGES`・`ASSETS` を確認し、必要な本番リソースを接続する。生成ファイルではなく、元の設定・ビルド設定を修正する。
- [ ] EmDash の初回起動時マイグレーションが完了することを公開前の環境で確認する。既存データがある場合は先にバックアップする。
- [ ] 診療所の受付も有効にする場合は、同じD1に `migrations/0001_inquiries.sql` を適用する。EmDash自身のテーブル初期化とは別の作業。

EmDashのCloudflare構成は[公式デプロイ手順](https://docs.emdashcms.com/deployment/cloudflare/)も参照する。現在のリポジトリは EmDash 1.4.0 を使用している。

## 2 管理者の初期登録

- [ ] 初期設定が完了するまで、第三者が初期管理者を登録できないアクセス制限を用意する。公開を担当する本人が初期設定画面にアクセスできることも確認する。
- [ ] 本番で使用するホスト名を確定し、そのホスト名上で本人がパスキーを登録する。仮ドメインで登録した認証情報を本番でも使える前提にしない。
- [ ] `/_emdash/admin` の初期設定で、管理者情報とパスキーを登録する。開発用の認証省略は本番手順に使わない。
- [ ] ログアウト後にパスキーで再ログインできること、未ログインでは記事の編集や管理APIを利用できないことを確認する。
- [ ] 予備の認証手段・管理者、端末紛失時の復旧方法を決める。
- [ ] 初期登録が終了したことを確認してから、一時的なアクセス制限を解除する。

## 3 記事とタグの設定

- [ ] `seed/seed.json` に沿って `posts` コレクション、タイトル・概要・本文フィールド、URL `/blog/{slug}` が作成されていることを確認する。
- [ ] タイムゾーンを `Asia/Tokyo`、サイトURLを `https://therethere.studio`、記事の言語を日本語にする。
- [ ] `posts` に taxonomy `tag` が関連付いていることを確認する。
- [ ] `tag` 内に slug **`app-clinic`**、表示名「AIアプリ診療所」のタグを用意する。スキーマのみの初期化ではseed内のタグ値が取り込まれない場合があるため、管理画面で存在を確認し、なければ作成する。
- [ ] 全記事の移行・初回公開対象を決め、記事ごとにslug、公開日時、概要を確認する。診療所向けの記事だけに `app-clinic` タグを付ける。

タグの仕様は[Taxonomies](https://docs.emdashcms.com/guides/taxonomies/)、初期データは[Seed files](https://docs.emdashcms.com/themes/seed-files/)を参照する。

## 4 管理画面からの動作確認

テスト記事を使い、確認後に削除するか正式な記事へ差し替える。

- [ ] タグなしの公開記事が `/blog` に表示され、`/app-clinic/blog` には表示されない。
- [ ] `app-clinic` タグ付き公開記事が両方の一覧に表示され、どちらからも同じ `/blog/{slug}` に遷移する。
- [ ] タグの追加・解除後に、診療所側の一覧と記事の診療所リンクが更新される。
- [ ] 下書き・未公開の予約記事が一覧とサイトマップに出ず、記事URLを直接開いても本文を閲覧できない。
- [ ] 予約公開時刻を過ぎると記事が公開される。Cronが有効で、Workerに実行エラーがない。
- [ ] 診療所の記事を13件以上用意して、2ページ目にもタグ条件が適用され、重複・欠落なく移動できる。
- [ ] 本文の見出し・リンク・画像がPCとスマートフォンで表示される。画像のアップロードと再表示でR2保存を確認する。
- [ ] 記事のcanonicalと `/sitemap.xml` が本番URLになり、未公開記事が含まれない。
- [ ] CMSの取得失敗時は記事がない状態として扱わず、503と再試行案内になる。

ローカルでは公開ページ・クエリ条件等を検証済み。パスキー登録を伴う本番管理画面の操作、実際の本番D1/R2、予約公開は公開作業で確認する。

## 5 ドメイン切替と運用確認

- [ ] ブログの確認と管理者初期登録を完了できる公開手順・時間を決める。本番ドメインでのパスキー登録が必要なため、切替と初期登録を一連の作業として行う。
- [ ] 公開を実施する段階で、現行 `therethere.studio` をこのプロジェクトのWorkerへ置き換える。現状の `npm run deploy` は本番向けなので、検証目的では実行しない。
- [ ] HTTPS、ホーム、旧製品ページ、旧URLのリダイレクト、`/app-clinic`、共通ブログを確認する。
- [ ] `/about` のnoindex、サイトマップからの除外、各プライバシーポリシーの日本語に続く英語掲載を確認する。
- [ ] 受付を開始する場合は `GOOGLE_CHAT_CONTACT_WEBHOOK_URL` と `CONTACT_ENABLED` を確認する。本人のテスト問い合わせで、D1への受付保存・通知・完了画面まで確認する。
- [ ] 不具合時に前のWorkerへ戻す手順と、D1の変更・投稿データをどう扱うかを確認する。WorkerのロールバックだけでDBは戻らない。
- [ ] D1・R2のバックアップ／復旧方法、エラーの確認方法、EmDash更新の担当と頻度を決める。

公開完了の条件は、本人の管理画面ログイン、通常記事と診療所記事の出し分け、画像保存、下書き非公開、既存URL維持の確認がすべて完了していること。
